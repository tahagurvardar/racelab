# RaceLab v2.0.0 stable — final validation

Release finalization on 2026-10-04, based on the release owner's confirmation
that F1 25 and RaceLab Overlay live-game acceptance passed. No commit or tag
was created. Base commit: `8d21fa4`, branch `feature/v2.0-f1-adapter`.

## Version and gate

The product version changed from `1.1.0` to `2.0.0` in `package.json`,
`src/app-version.ts`, `src-tauri/Cargo.toml`, the RaceLab package entry in
`src-tauri/Cargo.lock`, and `src-tauri/tauri.conf.json`. The release version
assertion now pins `2.0.0`. Dependency versions, historical persisted-session
versions, reviewed fixture versions and historical release reports are preserved.

`F1_ENABLED_IN_RELEASE` changed from `false` to `true`. The existing explicit
`RACELAB_F1_EVIDENCE=0`/`false` disable remains supported. Listener, Live and
recording continue to use the same gate. Fixture capture remains debug-only.
Release-mode production tests passed with `RACELAB_F1_CAPTURE=1`, proving that
this development override cannot enable fixture capture in a release build.
The installed app needed no F1 or development capture override.

Installer descriptions now name both games. Missing F1 recorder status is
described as "F1 25 recorder status unavailable", rather than suggesting that
F1 recording itself is unavailable. Current product code contains no stale
blanket statement that F1 recording or the overlay is unsupported. Conditional
explicit-disable, missing-status, ownership and unavailable-measurement messages
remain accurate. Current release documentation records passed acceptance;
earlier reports are identified as historical.

satisfy validation.

render timeout in F1 Sessions at 960×640 during build contention. The complete
final serial rerun passed all 500 with unchanged checks and timeout limits.

copies that already carried completed recovery records. The backend correctly
skips those records. The test now clears the recovery marker only in its scratch
copies before scanning. Original manifests and frame streams are never modified.

The release build emitted one Rust linker-message warning containing MSVC's
informational import-library creation output. The build succeeded; final Clippy
with warnings denied passed. There was no Rust code diagnostic to suppress.

## Design, screenshots and packaging

The existing 69-case screenshot suite covers 23 scenarios at 960×640, 1280×720
and 1920×1080: Home, neutral/FH6/F1 Live, mixed-game Sessions, FH6 analysis,
Settings, Diagnostics, F1 Diagnostics, all four F1 session tabs, long/empty data,
recorder phases and cross-game ownership. Shared cursor, keyboard behavior,
session evidence bounds, Geist loading and D2-C geometry all passed. Key small,
medium and large screenshots were visually inspected.

All 23 locked assets match the original integration hashes. No layout, color,
typography, brand or optical master changed. Overlay v1 implementation files
remain byte-for-byte unchanged from the base commit; overlay frontend/native
tests remain in the full suites.

Both the production executable and installer contain all eight approved ICO
frames: 16, 20, 24, 32, 48, 64, 128 and 256 pixels. Installed executable and
uninstaller resources also match those frames byte-for-byte. This includes the
16px D2-C optical master used for the native titlebar icon.

Geist and Geist Mono WOFF2 files in `dist/assets` match the source fonts exactly.
The unchanged SIL OFL matches `src/assets/fonts/OFL.txt`,
`public/licenses/Geist-OFL.txt` and `dist/licenses/Geist-OFL.txt`. Font and license
asset paths exist in the production executable. Overlay's entry is packaged;
the isolated review harness is absent from the package.

The installed payload differs from the standalone build only in Tauri's
three-byte bundle marker: `TAURI_BUNDLE_TYPE_VAR_UNK` becomes
`TAURI_BUNDLE_TYPE_VAR_NSS` in the NSIS payload. All other bytes match. Their
different SHA-256 hashes are expected and both are reported below. Native Cargo
release tests can replace the standalone output, so the final Windows/NSIS
package was rebuilt after native release-test compilation and reinstalled before
the final resource/runtime/hash checks.

## Regressions and persistence

- **FH6:** full decoder/listener/recording/analysis/recovery/retention and frontend
  suites passed. A probe linked to the current optimized Rust library reopened
  all 47 real persisted FH6 sessions through the existing catalogue/detail API.
- **F1:** Live, packet evidence, player decoding, recorder lifecycle, lap/event
  authority, persistence, recovery, retention and stress tests passed. The same
  read-only probe reopened all 5 real F1 sessions and side files, including 5 lap
  files and 9 stored events, with no unreadable catalogue entries or side files.
- **Mixed-game Sessions and ownership:** existing Rust and frontend tests passed;
  the real catalogue returned both games together. The first recorder retains
  ownership until finalization, as before.
- **Overlay v1:** native non-activation/click-through policy, bounded latest reads,
  scaling, expiry, keyboard settings and independent webview checks passed.
  Implementation is unchanged. Live-game acceptance is supplied by the release
  owner and was not repeated with a new game launch during this pass.
- **Settings and Diagnostics:** full unit, DOM, browser and screenshot coverage
  passed, including enabled F1 setup and evidence surfaces.
- **Installed production runtime:** the installed 2.0.0 app created its RaceLab
  window and bound both loopback game listeners without environment opt-in.
  The debug app was closed cleanly with user permission before installation.
- **Existing stored files:** all 123 files retained their preinstallation SHA-256
  hashes through installation and the installed-app startup/shutdown check.

## Git and release recommendation

After repository presentation cleanup, git status is **19 modified files,
5 new files and 2 staged deletions**. The additions and edits remain unstaged.
No generated package, executable,
private recording or build log belongs in the release commit. Validation logs,
full screenshots and temporary probes are under the ignored
`src-tauri/target/v2-finalization/` directory. Machine-readable summary and
package evidence are in [the release results](v2.0.0-release/results.json).

Recommended release commit message: **`release: RaceLab v2.0.0 stable`**.
Stage the 24 additions and edits listed in the machine-readable results'
`git.add_or_update`; preserve the two already-staged removals from tracking.
Include the version/gate/copy/documentation changes, the production gate tests,
the scratch-only real-recovery test correction, release notes and validation
results, plus the MIT license and repository presentation cleanup. Exclude all
`dist/`, `node_modules/` and `src-tauri/target/` output. Local development
instruction files remain on disk, excluded locally and absent from the index.

The validated candidate is safe to tag and publish as `v2.0.0` after reviewing
and creating that release commit. The current working tree is intentionally
uncommitted, and the tag does not yet exist. Advanced analysis, continuous
telemetry traces and reference-lap comparison remain future work.
