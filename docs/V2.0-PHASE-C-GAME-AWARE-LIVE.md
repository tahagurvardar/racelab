# V2.0 Phase C — game-aware shell and F1 25 Live

RaceLab now presents whichever supported game is sending: Forza Horizon 6 or
F1 25. This phase adds no F1 recording, no F1 analysis and no change to FH6
behaviour, to persisted formats or to the V1.1 visual design.

## Active game

`src/telemetry/games.ts` holds the logic and is pure:

- `fh6Facts` reads the backend's own FH6 connection state.
  - `SESSION_ACTIVE` / `CONNECTED_IDLE` are fresh: active while driving,
    detected otherwise.
  - `GRACE` and a frameless `DEGRADED` are stale.
  - Anything else is inactive.
- `f1Facts` reads `get_f1_live`.
  - An accepted packet of any type within 2 s means fresh. That is the
    backend's detection window.
  - It is active when the player's Car Telemetry family is fresh and a player
    car exists, and detected otherwise.
  - Silent for 2–10 s is stale; longer is inactive.
- `arbitrate(previous, facts)` is sticky:
  - The selected game keeps the screen while it is fresh, even if the other
    game is fresh too.
  - It switches only to a game that is fresh.
  - With nothing selected, it takes the only fresh game, or the most recent
    of two (ties go to FH6, then F1 25).
  - With nothing fresh, nothing is selected. One exception: a single held
    game (FH6 grace or fault, F1 25 briefly silent) keeps or takes the screen,
    so "Paused" and "Telemetry degraded" keep their V1.1 meaning.

`src/state/active-game.ts` is a derived store and the only writer of
`activeGameStore`. It subscribes to the FH6 and F1 live stores, recomputes
synchronously, and notifies only when the choice or a game's activity changes.
It works identically in the app and in jsdom tests, with no React owner.

## Data flow

| Store              | Owner (only writer)          | Rate   | Readers                                                    |
| ------------------ | ---------------------------- | ------ | ---------------------------------------------------------- |
| `liveStore` (FH6)  | `hooks/use-live-telemetry.ts` | 20 Hz  | `Fh6LiveWorkspace`, Diagnostics; derived: top bar, sidebar |
| `f1LiveStore`      | `hooks/use-f1-live.ts`        | 10 Hz  | `F1LiveWorkspace`; Settings selects coarse facts only      |
| `f1Store` (evidence) | `hooks/use-f1-evidence.ts`  | 4 Hz   | Diagnostics → F1 25                                        |
| `activeGameStore`  | `state/active-game.ts`        | on change | router, top bar, sidebar, first run, Sessions, Settings |

- `get_f1_live` is a new compact backend command. It returns the listener
  state, the age of the latest accepted datagram, and the decoded player
  families. It carries no counters, sizes, header identifiers or capture
  state.
- `LiveWorkspace` routes to `Fh6LiveWorkspace` (V1.1 code, moved), to
  `F1LiveWorkspace`, or to the neutral waiting view.
- Only one game's workspace and only its open tab are mounted. Tests check
  that F1 updates render nothing in the shell frame, Sessions or Settings.

## F1 25 Live

There are four F1-specific tabs. They share the tab position with FH6's
tabs, so the 1–4 shortcuts keep working.

- **Overview:** speed, gear (R/N/1–8) and RPM first, with the RPM bar running
  from the car's idle to its max. Inputs: throttle, brake, signed steering
  and clutch. Car state: DRS, DRS allowed and DRS distance as three separate
  facts; ERS store (J ÷ 10⁶ = MJ) and mode; fuel; front brake bias. Then the
  lap strip, and "Recording: not available for F1 25 yet".
- **Race:** lap, times and sectors, lap validity, distance, safety-car delta,
  standing, driver and result status, pit state and timers, penalties and
  warnings, this lap's ERS energy (no unit is stated, so shown as sent), and
  the speed trap.
- **Tyres:** tyre set (actual and visual compound, age). Below it, four
  corner cards in physical layout with surface, inner and brake temperatures,
  pressure, wheel speed, slip ratio and angle, suspension position, vertical
  force and surface type. There are no thresholds, health verdicts or
  wheelspin/lockup labels.
- **Dynamics:** local velocity, angular velocity and acceleration, attitude
  scalars, and every per-wheel Motion Ex channel in a table. Nothing derived.

Wheels: the backend turns the wire order (RL, RR, FL, FR) into named corners
once. `src/telemetry/f1-wheels.ts` is the only frontend module that maps those
names to presentation order. An architecture test enforces that, and keeps F1
and FH6 presentation from importing each other.

## Freshness

Defined in `src/telemetry/f1-freshness.ts`, per family (telemetry, status,
lap, motion):

- **Fresh:** at most 1 s old. The captured 441 ms high-speed snapshot is fresh.
- **Stale:** 1–3 s old. Values are shown dimmed, with "not updating" for
  screen readers and a "Not updating · 1.8 s" badge.
- **Unavailable:** older than 3 s, or never received. The values are hidden.

One family going quiet affects only the values from that family. There is no
interpolation.

## Other surfaces

- **Top bar:** "Waiting for a supported game" with no game or facts beside it.
  "Live" or "Connected · not driving" next to "F1 25", or the FH6 states,
  unchanged, next to "Forza Horizon 6". F1 facts are Lap and Position; the F1
  popover says sessions are not recorded.
- **First run:** the pill reads "Set up a supported game". The FH6 setup
  guide is hidden while F1 25 is active, and points F1 players to Settings.
- **Settings:** a new F1 25 group shows its status and the game's own menu
  entries (UDP Telemetry On, Broadcast Off, 127.0.0.1, port from the backend,
  20 Hz, Format 2025). Those labels are marked `data-game-menu`, the only
  place "UDP" may appear in product text. There is no capture control.
- **Sessions:** while F1 25 is active, one line: "F1 25 session recording is
  not available yet." No fake entries and no format change.
- **Diagnostics:** unchanged. It keeps all Phase A/B evidence and the capture
  tooling.

## Known limitations

- The FH6 first-run record is persisted. An F1-only user still sees the FH6
  guide whenever F1 25 is not running, because it only steps aside while F1 is
  active. Fixing this needs a new settings field, which is deferred.
- The F1 listener is still on only in debug builds or with
  `RACELAB_F1_EVIDENCE=1`. A release build shows "F1 25 support is not
  enabled in this build". Enabling it in release is a product decision, since
  it claims port 20777.
- If both games run and FH6 is recording, the top bar's REC indicator belongs
  to FH6 while F1 25 may be the game on screen.
- A live DRS-on transition has not been observed (all four fixtures have DRS
  off). The HUD comparison is pending.

## Manual acceptance

1. Start RaceLab (dev) with no game running. Live and the top bar should read
   "Waiting for a supported game".
2. Start F1 25 (UDP on, 127.0.0.1:20777, Format 2025). RaceLab should switch to
   F1 25 on its own.
3. In Time Trial, check that speed, RPM, gear, throttle, brake, steering and
   lap data respond, and that tyre/brake temperatures, pressures, fuel and ERS
   appear.
4. Open DRS if possible and confirm DRS reads "On". If DRS cannot be opened,
   record it as unverified.
5. Compare speed, gear and RPM with the F1 HUD. This is a check only: no
   decoder value is to be tuned to match.
6. Pause F1 25 and watch the top bar and badges move to "Connected · not
   driving" / "Not updating", and then to "Paused" if telemetry stops.
7. If practical, run FH6 briefly and confirm FH6 Live is unchanged.

Screenshots of the harness rendering the real fixtures are in
`docs/v2.0-phase-c/`.
