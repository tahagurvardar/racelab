# RaceLab V0.4 — FH6 adapter and offline validation

Implemented and tested on Windows, 2026-09-18. The frozen UDP `ingress.rs` and `packet.rs` are unchanged. Existing V0.3 working-tree changes were retained; this report describes the additional V0.4 work. No full private capture was copied into the repository or uploaded.

## Result

The adapter implements every requested offset in the [complete protocol table](FH6-PROTOCOL.md#exact-implemented-offsets). Exact byte widths, little-endian decoding and signedness are tested. Engine/motion/control fields also have real-packet golden comparisons and physical consistency checks. This corroborates the supplied layout; it does not independently prove every field's unit or enum meaning.

`TelemetryFrame` contains game-independent engine, motion, position, speed, normalized controls, activity and game timestamp. The separate `Fh6Raw` extension retains vehicle fields, remaining dash values and unknown regions. Inactive packets produce zero dynamic canonical telemetry. Unsupported lengths, invalid activity/steering and every non-finite implemented f32 are reported. Offline/live validation applies declared speed/RPM policies and timestamp checks.

Tauri attaches a composite `PacketSink`: raw capture first, then FH6 validation. Adapter rejection does not reject raw capture. Live state is bounded to the latest result and counters. The existing 4 Hz publisher adds live snapshots; command wrappers serialize listener transitions and adapter reset without changing the Listener implementation. The UI adds only six metric cards using existing styles: speed km/h, RPM, gear code, throttle %, brake %, steering %. Invalid/stale/stopped live fields are unavailable; inactive dynamic telemetry is zero. Staleness threshold is two seconds.

- All datagrams were **324 bytes**; all capture footers recorded **zero capture drops**.
- All implemented float fields were finite, including inactive packets. No invalid activity flags or steering values were found.
- Active speed agreed with the f64 magnitude of stored velocity components within **1.0300189e-5 m/s**. Validation policy allows **0.001 m/s** of rounding headroom; the measured maximum is reported without rounding it down to the threshold in the request.
- Active current RPM was nonnegative and within the policy bound. The highest current/max RPM ratio was **0.9449300811** (94.493%). Idle/max RPM checks also passed.
- Active throttle and brake were **0..255** overall; steering was **-127..127**. Capture 05's active brake values were all zero. Byte decoding inherently bounds unsigned pedals; endpoint and invalid-signed-byte tests verify normalization and steering rejection.
- There were **zero timestamp regressions, wraps, inactive-boundary resets or explicit resets** in all six files. Reset/wrap handling is therefore validated by synthetic tests, not claimed as observed game behavior.
- Observed active gear codes collectively include **0, 1, 2, 3, 4, 5, 6, 11**. The adapter preserves numeric codes rather than assigning unverified reverse/neutral meanings.

These statistics establish consistency of the recorded datagrams. They do not prove that UDP/game/OS delivery had no loss before ingress or that filename labels describe isolated driving inputs.

## Minimal fixture validation and privacy

The six public fixtures contain **18 real-derived packets**: 12 active and six inactive. Each file is **1,198 bytes**, for **7,188 bytes of binary fixtures total**. Each passed RLCAP, adapter, physics and timestamp validation with zero drops/errors. Maximum fixture speed discrepancy is **0.000003532369 m/s**. [Per-fixture results](v0.4-validation/fixtures.json)

Fixture bytes retain exact original engine/motion/speed/control data. Redactions remove bytes 68..255, 292..314 and 321..323, including unknown regions, vehicle identity/configuration, position, distance and race/lap context. Game/monotonic clocks are rebased, labels become sample numbers, source becomes 127.0.0.1:0 and wall timestamps become zero. Full source files remain private. See [fixture provenance and extraction instructions](../src-tauri/tests/fixtures/fh6/README.md).

The Node extractor independently produces golden f32/control values and SHA-256 digests. Rust tests compare decoded and normalized fields against the golden manifest. Node integrity tests check digests, file sizes, counts and redaction ranges. Synthetic byte-sentinel tests verify vehicle, position, race/lap fields and exact preservation of unknown bytes, because those bytes are deliberately removed from the public real fixtures.

## Remaining uncertainty

Bytes **232..243** and **321..323** remain explicitly unknown; **68..211** remains unimplemented/opaque. Wheel temperature order/units, auxiliary dash units/sentinels, vehicle/drivetrain enums, gear semantics, axis conventions and game reset behavior need further evidence. The exact offset table separates decoded fields from these unresolved meanings. No unknown bytes are interpreted as meaningful values in the canonical model or UI.
