# RaceLab V0.2.2 validation

**Freeze assessment: ready to freeze as the narrow V0.2.2 ingress baseline on the tested Windows host, with the limits and intermediate failures below retained.** The requested matrix received **14,000/14,000 packets**, with **zero missing sequences and zero receive errors**. Removing SO_RCVTIMEO eliminated the previously observed failure in this tested matrix. This does **not** prove the historical root cause or establish a universally safe timeout. No timeout was substituted.

## Narrow change

Production UDP receives now block without setting SO_RCVTIMEO. The 4 MiB SO_RCVBUF request is unchanged. No game parsing or UI redesign is included; the UI's version label alone advances to V0.2.2.

Stop sets the session's atomic stop flag, sends a private datagram to 127.0.0.1 at the bound telemetry port, then joins the receiver. Each session reserves its own loopback source socket and generates a fresh 32-byte OS-random nonce through getrandom 0.3.4 (already present in the dependency lockfile). A control packet must match both the exact source address and the complete nonce. It is filtered before statistics or PacketSink delivery, including when received without a stop request. After stop is signalled, any queued ordinary packet also lets the worker exit; stop does not promise to drain queued telemetry.

The wake sender is nonblocking and performs one checked send. A failed wake send reports a lifecycle error and retains the worker handle for a retry; it never proceeds to join a receiver that might still be blocked after a failed wake. No polling or sleep loop is used in production. Interrupted receives retry; all other socket receive errors increment the existing error counter and stop the session. PacketSink, session-relative monotonic capture times and the independent 4 Hz publisher are retained.

## Validation conditions

Windows loopback, 128-byte synthetic datagrams, the production Listener implementation, sequential load cases. Every load socket keeps the existing 4 MiB request. Winsock readback is an accepted/read-back option value, not guaranteed OS allocation or queue capacity. The PowerShell sender records every send return value; the bounded observer checks every sequence, duplicates, malformed traffic, final sequence 1000 and monotonic capture timestamps.

The requested matrix is five 10 Hz runs and three each at 20, 60 and 120 Hz, all 1,000 packets. Each run includes the existing 2.2-second idle PPS check and 4 Hz snapshot sampler. Sender elapsed time excludes process startup and receiver cleanup; case elapsed time includes these. Raw sender and receiver TSVs are retained in v0.2.2-load/.

## Intermediate failures retained for transparency

- The initial parallel library suite reported 10 passed / 2 failed: the original idle-test watchdog capped all 20 cycles together at five seconds, and the existing restart test timed out waiting for one zero-length datagram. The zero-length test passed unchanged in isolation in 0.02 seconds; this does not establish why its first wait expired.
- The idle test was corrected to use a watchdog per cycle, retaining its independent 500 ms stop-latency limit. A later parallel run reported 11 passed / 1 failed: one stop took 531.8035 ms. The isolated 20-cycle run passed, with a maximum stop of 6.1537 ms. Concurrent builds/tests and a game process were present; attributing the timing failures exclusively to scheduling is an inference, not a proven diagnosis.
- An attempted full Rust build while the load binary was running failed with Windows LNK1104 because that executable was in use. After the matrix, the full suite passed both serially and with the default parallel runner, without relaxing the 500 ms stop-latency bound. The failed build and test outputs are retained.

## Remaining limits

Passing synthetic loopback tests cannot prove the historical root cause or universal loss-free delivery. UDP and OS scheduling remain outside the application's guarantees. A sink that violates its prompt-return contract can delay ingestion and stop. Stop relies on delivery of its private loopback wake when the receive queue is empty; a successful UDP send is not a formal delivery guarantee. Repeated quiet-stop tests validate the normal path, not arbitrary OS/network failure. Real game payload sizes, bursts and network conditions remain unvalidated.

## Reproduce

Run from the repository root; execute build/test commands sequentially on Windows so the linker does not try to replace a running test executable. Preserve existing evidence before rerunning the load matrix because it overwrites same-named traces.

~~~powershell
pnpm format
pnpm format:check
pnpm check
pnpm test:frontend
pnpm build
cargo check --manifest-path src-tauri/Cargo.toml --all-targets
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml -- --nocapture
pnpm test:udp
~~~
