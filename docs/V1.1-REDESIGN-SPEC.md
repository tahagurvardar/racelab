# RaceLab V1.1 — Product Redesign Specification (Stage A)

Status: **proposal for review**. No product code has changed. Baseline when this
was written: `feature/v1.1-product-redesign` @ `de32f62` (V1.0.0), 172/172
frontend tests passing, `tsc --noEmit` clean.

Scope: frontend presentation and UX only. The V1.0 boundaries in the brief
(ingress, decoder, `TelemetryFrame`, SessionEngine, recorder, RLFRAMES,
recovery, retention, V0.9 analysis semantics, units, wheel mapping) are
untouched by everything below. Where a proposal comes close to one, it is
called out under **§10 Decisions needed**.

## 1. What exists today

### 1.1 Structure

| Layer | Files | Notes |
|---|---|---|
| Shell | `App.tsx`, `components/AppShell.tsx`, `components/StatusBar.tsx`, `views/navigation.ts` | Plain `useState<ViewId>` switch, no router. All four subscriptions live in `App`. |
| Subscriptions | `hooks/use-live-telemetry.ts` (20 Hz poll), `use-recorder-status.ts` (2 Hz), `use-setup-state.ts` (1 Hz), `use-transport-stats.ts` (4 Hz event) | Architecture tests pin these to exactly three pollers + one listener, mounted once. |
| View models (pure, tested) | `telemetry/telemetry-view-model.ts`, `diagnostics-view-model.ts`, `setup-view-model.ts`, `formatting.ts`, `session-state.ts`, `analysis-state.ts`, `settings-state.ts` | Strong layer: every string, unit and "unavailable" decision is made here, not in components. **Keep it.** |
| Components | `MetricCard/MetricGrid`, `TelemetrySection/ViewHeader`, `InputBar/RangeBar`, `WheelTelemetry`, `EmptyTelemetryState/UnavailableChannel`, `FirstRunGuide`, `StorageBudget` | Generic; one visual primitive (the card) carries almost everything. |
| Views | 7 live views, `SessionsView` (632 lines, owns its own IPC), `DiagnosticsView` + `CapturePanel` | |
| Styling | one `styles.css` (938 lines) | Tokens exist but are partial. |

The view-model layer is the best part of the frontend and is the reason this
redesign can be presentation-only: the new UI consumes the same models.

### 1.2 Navigation problems

1. **Nine flat destinations with equal weight.** Seven live channel pages, then
   Sessions, then Diagnostics. Sessions is a different *mode* (history vs live)
   but sits as the eighth item of the live list under the heading "Telemetry".
2. **Three live pages are too thin to be pages.** Race holds 5 values (4 more
   are permanently unavailable). Suspension holds 8 numbers. Inputs holds 5 bars,
   3 of which are already on Overview.
3. **No home for settings.** The single setting (storage budget) is embedded
   inside Sessions; the listener port control is in Diagnostics; the FH6 setup
   instructions vanish forever after first detection with no way back.
4. **Product states route the user to engineering.** The "listener stopped"
   empty state says "Start it from Diagnostics".
5. **Every nav item has a two-line hint** ("RPM range and output"), making the
   sidebar tall and noisy for no gain after the first visit.
6. **Below 900 px the sidebar turns into a wrapping top bar** — a mobile pattern
   in a desktop app whose window minimum is 720 px.

### 1.3 Information hierarchy problems

- **Implementation prose in headers.** Every view opens with a summary written
  for reviewers: "Every reading comes from the normalized TelemetryFrame; no
  adapter value appears here." Every section has a `CANONICAL …` eyebrow.
  Sessions and Diagnostics carry release history as eyebrows: `V0.6 · MANIFEST
  METADATA ONLY`, `V0.9 · DERIVED ANALYSIS`, `V0.2.2 · FROZEN INGRESS`.
- **Equal-weight card grids.** Overview gives speed, RPM and gear identical hero
  cards, then gives *Vehicle ID* and *Cylinders* the same section weight as
  driver inputs. Power, tire temperature and slip — the things a driver looks
  at — are not on Overview at all.
- **The gear hero is almost always "—".** FH6 gear semantics are unvalidated
  (`GEAR_UNVALIDATED`), so a third of the hero row is a dash with a paragraph.
- **Duplicates without purpose.** Power in kW *and* W; acceleration in m/s² *and*
  g as two full grids; wheel rotation in rad/s *and* rpm; current RPM as hero
  *and* as a card directly below it.
- **Unavailable data occupies full sections.** Engine "Fluids and boost", Tires
  "Surface contact", Race "Lap timing and distance" are whole dashed-card
  sections for fields that never exist. Race is mostly unavailable data.
- **Idle looks broken.** With no live frame every view is a full page of em
  dashes under a small status panel. Correct (never zero), but not calm.
- **Status bar has overlapping chips.** Connection *and* Health *and* Session
  *and* Recording, each an uppercase micro-label + value pill. "Connected / Good
  / Session active / Recording" is four chips for one fact: "live, recording".

### 1.4 Sessions problems (highest-impact area)

- **Detail renders below the list.** Clicking *Open* on row 14 of 20 puts the
  session detail ~20 rows further down, off screen, with no scroll and no
  selected-row indicator. This is the single worst UX defect in the product.
- **One endless scroll**: Recorder internals → Storage setting → List →
  Details → Analysis → four unbounded event lists → data quality → seven
  paragraphs of heuristic definitions.
- **Recorder internals as product content**: "Queued frames 0 / 4096", "Frames
  written", raw session id. These already exist in Diagnostics.
- **Analysis is fetched once on open.** A queued/analyzing session tells the user
  to "Reopen it in a moment" — the UI makes them poll by hand.
- **Rich analysis data is unused**: `events_by_kind`, `max_longitudinal_
  acceleration_mps2`, `hard_braking_seconds`, `slip_episode_seconds`, `max_speed_
  mps` exist in `driving_summary` but only the four counts are shown. There is no
  timeline, though every event/turn/episode carries `start_ms`/`end_ms`.
- **Events render as stacked bordered cards** (one panel per event), not as a
  table, so columns never align and 100+ events is a very long page.
- **Technical leakage**: raw `completion_reason` enum, `created_by_racelab_
  version`, `analysis.json` file name in the re-run copy, "schema v2" in the
  available-state detail line.
- **Inconsistent error rule**: `SessionsView` shows `recorder.last_error` whenever
  it is set (`SessionsView.tsx:199`), while `buildStatus` deliberately ignores a
  stale `last_error` once the recorder has recovered. The same stale error
  alarms in one place and not the other.
- **Re-renders at 20 Hz.** `SessionsView` is a child of `App`, which re-renders on
  every live snapshot, so the list and all analysis rows are rebuilt every 50 ms
  while the user is reading history.

### 1.5 Diagnostics problems

Content is right for an engineering surface; presentation is not:
`CapturePanel` is a `.panel` nested inside a `.panel` section and repeats its
own eyebrow/title (`V0.3 · EXACT RAW DATAGRAMS` twice); one inline style; the
listener port input defaults to a hard-coded `20440` rather than the bound port
from `get_setup_state`; recorder queue health is duplicated with Sessions.

### 1.6 Design-system gaps

- **26 distinct font sizes** (0.6rem … 1.5rem in ~0.02rem steps) and **12
  letter-spacing values**; no type scale.
- **Raw colours outside tokens**: `#5c2f2f` ×4, `#1d1214` ×2, `#ffb4b4` ×2,
  `#c4cdd7`, `#ff9a9a`, `#0a0c0f`. No error/warning surface tokens.
- **Contrast**: `--text-dim #6d7883` on `--surface #121519` is ≈4.0:1 and is used
  for 10–11 px uppercase labels. Fails WCAG AA for small text.
- **Radius 14 px panels / 10 px cards / 999 px pills** read as generic SaaS.
- **Accent is defined but almost unused** (focus ring and the setup edge only);
  input bars and RPM bar are all the same grey, so throttle and brake are not
  distinguishable at a glance.
- **No motion tokens, no hover/active/disabled system** beyond `opacity: .45`.
- **No brand**: the mark is a 10×22 px two-tone gradient bar; the version is a
  literal `<em>V1.0.0</em>` (pinned by `release-config.test.mjs`).
- `Inter` is first in the stack but not bundled; Windows renders Segoe UI.
- Window opens at **1120×760, min 720×560** (`tauri.conf.json`) — below the
  brief's 1280×720 primary target.

## 3. Design principles

1. **Hierarchy over grids.** One primary reading per region; secondary readings
   are smaller, not boxed separately. Cards are for grouping, not for every value.
2. **Calm when idle, expressive when live.** No frame → the dashboard dims to a
   single state statement. Colour and motion appear only with live data.
3. **Honesty is a visual rule, not a paragraph.** "Unavailable is not zero" is
   kept everywhere, expressed by a consistent unavailable treatment (dim dash +
   info affordance) rather than prose on screen. The prose moves into an info
   popover/disclosure; it is never deleted.
4. **Product language in product surfaces, engineering language in
   Diagnostics.** No version numbers, schema numbers, file names, enum values or
   the word "canonical" outside Diagnostics and the Session › Data tab.
5. **No meaning the data does not establish.** No traffic-light colouring of tyre
   temperature, slip or RPM (no "optimal window", no shift light), no left/right
   for yaw sign, no lateral/longitudinal for vector axes. Semantic colour is used
   only where the convention is about the *channel*, not a judgement (§5.6).

## 4. Information architecture

### 4.1 Top level

```
┌──────────┬────────────────────────────────────────────────────────────┐
│ ◢ RaceLab│  TOP BAR  ● Live · Forza Horizon 6   Vehicle 3421   12:04   ● REC │
│          ├────────────────────────────────────────────────────────────┤
│ ◉ Live   │  [alert slot — only when something needs attention]        │
│ ▤ Sessions│                                                           │
│ ⚙ Settings│  WORKSPACE                                                │
│          │                                                            │
│ ──────── │                                                            │
│ ⌁ Diagnostics                                                         │
│   v1.0.0 │                                                            │
└──────────┴────────────────────────────────────────────────────────────┘
```

| Section | Purpose | Sub-navigation |
|---|---|---|
| **Live** (default) | What is happening now | Segmented tabs: **Overview · Engine · Corners · Motion** |
| **Sessions** | Recorded history and analysis | Master–detail; detail tabs **Summary · Events · Turns · Slip · Data** |
| **Settings** | Storage limit, game setup instructions, about | Single page, three groups |
| **Diagnostics** | Engineering console, visually separated at the bottom | Tabs **Connection · Pipeline · Adapter · Capture** |

Rationale:
- Four destinations instead of nine; the mode split (live / history / config /
  engineering) is what the user actually navigates by.
- Race and Inputs fold into Overview (they are what a driver glances at);
  Tires + Suspension become **Corners**, one block per wheel, because per-corner
  is how the data is organised and read; Dynamics becomes **Motion** and also
  receives the exact timing values.
- Live remembers its last tab; keyboard: `Ctrl+1..4` sections, `1..4` Live tabs.
- Navigation stays a plain value (`{ section, liveTab, diagnosticsTab }`), no
  router — consistent with the existing rationale in `navigation.ts`.

### 4.2 Sidebar

200 px expanded, 56 px icon rail below 1200 px content width (no wrapping top
bar). Single-line items with inline SVG icons, no hints. Mark + wordmark at top,
version in the footer. Diagnostics sits below a divider with dimmer styling.
Live item carries a small live/rec indicator so state is visible from Sessions.

### 4.3 Top bar (replaces StatusBar chips)

One **primary state** computed by a new pure resolver (`product-state.ts`, §7)
plus facts:

`[state dot] Live · Forza Horizon 6    Vehicle 3421    Session 12:04    ● REC`

Clicking the state opens a compact popover listing the four underlying readings
(Connection, Health, Session incl. grace countdown, Recording) exactly as
`buildStatus` produces them today — nothing is removed, it is just not four
pills wide. The `● REC` element is the only persistent red in the app.

A test asserts no raw hex/rgb outside the tokens file (§9).

### 5.3 Colour — brand, status, telemetry

| Token | Value (approx.) | Rule |
|---|---|---|
| `--accent` | `#5AA8FF` | interactive: selection, focus, active tab, links. Never data. |
| `--status-ok` | `#4FCB86` | connected / complete / available |
| `--status-warn` | `#E5B454` | paused, degraded, queued-long, storage near limit |
| `--status-bad` | `#F0605D` | failed, error, data loss |
| `--status-info` | `--text-2` | neutral state |
| `--rec` | `#FF4D4D` | recording dot only |
| `--*-surface` / `--*-border` | tinted 8–12% / 30% of each status | alert backgrounds (replaces `#1d1214`, `#5c2f2f`, `#ffb4b4`) |
| `--ch-throttle` | `#4FCB86`-family | throttle bar/trace |
| `--ch-brake` | `#F0605D`-family | brake bar/trace |
| `--ch-steer` | `#A9B2BD` | steering, clutch, handbrake (neutral) |
| `--ch-scale-0..4` | single-hue (blue-grey → off-white) luminance ramp | tyre temp / slip magnitude intensity, always with the number printed |

Throttle-green / brake-red is a channel-identity convention used across
motorsport telemetry, not a judgement. It is the only semantic hue on Live.

### 5.4 Typography

System fonts only (no new dependency, no bundled font files):
- **Sans** `"Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif`
- **Display numerals** `"Segoe UI Variable Display", "Segoe UI", …` with
  `font-variant-numeric: tabular-nums` — readings never jitter at 20 Hz.
- **Mono** `"Cascadia Mono", Consolas, ui-monospace` — **only** for machine
  strings: IDs, hex, paths, raw adapter values, packet offsets, codes.
  Ordinary numbers use tabular sans, not mono.

| Token | px / line | Weight | Use |
|---|---|---|---|
| `--type-hero` | 72 / 1 | 600, −0.03em | Overview speed |
| `--type-display` | 44 / 1 | 600, −0.02em | secondary hero (RPM, Engine RPM) |
| `--type-figure` | 24 / 1.1 | 600 | KPI figures, corner primaries |
| `--type-title` | 18 / 1.3 | 650 | workspace titles |
| `--type-heading` | 14 / 1.3 | 650 | panel headings |
| `--type-body` | 13 / 1.5 | 400 | default UI text |
| `--type-small` | 12 / 1.45 | 400 | captions, table cells |
| `--type-label` | 11 / 1.2 | 600, +0.06em, uppercase | field labels (≤ 2 words) |

Eight sizes replace twenty-six. Hero sizes scale with container queries.

### 5.5 Spacing, radius, elevation

- Spacing: 4-pt scale `--sp-1..8` = 4, 8, 12, 16, 20, 24, 32, 48.
- Radius: `--r-1: 2px` bars/tracks · `--r-2: 4px` controls, chips, rows ·
  `--r-3: 6px` panels · `--r-pill` status pills only.
- Elevation: none on panels — hierarchy by surface tone + 1 px border. One
  shadow token `--shadow-overlay` for popovers/menus only.

### 5.6 Interaction states

| State | Treatment |
|---|---|
| hover | background → `--surface-3`, text → `--text` (120 ms) |
| active/pressed | background one step darker, no translate/scale |
| selected | `--surface-3` + 2 px `--accent` leading edge |
| focus-visible | 2 px `--focus` ring, 2 px offset, never removed |
| disabled | `--text-disabled`, border `--border-subtle`, `cursor: not-allowed`; no opacity hack on children |
| unavailable value | `—` in `--text-disabled` + ⓘ affordance carrying the existing `note` (tooltip on hover/focus, readable by screen readers) |

Buttons: **primary** (accent fill, dark text), **secondary** (border-strong
outline), **quiet** (text only), **danger** (bad-outline; only "Stop listener"
and "Stop capture").

### 5.7 Components to build

`Icon` (inline SVG set, ~12 glyphs), `Wordmark`, `AppMark`, `Sidebar`,
`TopBar`, `StatePill`, `StatePopover`, `Tabs` (segmented, keyboard),
`Panel` (header/body/footer slots, no nested panels), `Readout` (label · value ·
unit · unavailable handling — replaces `MetricCard` for most uses),
`HeroReadout`, `ChannelBar` (signed/unsigned, channel colour), `RangeBar`,
`CornerPlan` (four-corner car plan view), `KeyValueTable` (Diagnostics/Data),
`DataTable` (sticky header, numeric right-align, bounded rows + "Show more"),
`Timeline` (SVG, session time axis), `Alert` (info/warn/bad, title + body +
optional technical detail disclosure + optional action), `StateScreen` (centred
state for empty/first-run/idle), `Meter` (storage usage), `InfoTip`.

`MetricCard/MetricGrid` remain for Diagnostics-style grids only if still needed.

## 6. Brand

- **Wordmark**: `RaceLab` set in Segoe UI Variable Display, 650, −0.02em;
  "Race" in `--text`, "Lab" in `--text-2`. Rendered as a React component (text +
  optional mark), not an image, so it stays crisp at any DPI.
- **App mark — "Apex trace"** (recommended): 20×20 SVG, `--r-1` squared frame,
  inside it a single stroked path that runs straight → arcs → straight (a
  racing line through a corner, equally a telemetry trace), with a filled dot at
  the apex in `--accent`. `currentColor` stroke so it works on any surface.
  Alternative for review: a slanted "R" monogram built from two parallel
  telemetry strokes. Both delivered as inline SVG in Stage B for comparison; no
  binary icons are generated.
- **Usage**: mark + wordmark in sidebar header; mark alone in the 56 px rail;
  version `v1.0.0` in sidebar footer in `--type-small`, `--text-3`. The product
  is always "RaceLab" (never "Racelab", "RACELAB" except as a `--type-label`).

## 7. Product states

### 7.1 One resolver

New pure module `src/telemetry/product-state.ts` (no React, node-testable):

```ts
resolveProductState({ snapshot, stats, recorder, setup, liveError,
                      connectionError }) → { kind, tone, title, detail, action? }
```

It composes existing outputs (`resolveLiveFrame`, `connectionPresentation`,
`sessionPresentation`, `recordingPresentation`, `resolveSetupStage`) — it adds
priority ordering, not new semantics. Every input below is an existing field.

### 7.2 State table (priority high → low)

| State | Source signal (existing) | Top bar | Live workspace |
|---|---|---|---|
| Backend unreachable | `liveError` / `connectionError` | ✕ "RaceLab service not responding" | StateScreen + raw error in detail disclosure |
| Recording failure | `recorder.status === "error"` | ✕ "Recording failed" | Alert (bad) above dashboard; `recorder.last_error` in detail |
| Listener stopped / port error | `!stats.running`, `connection === "ERROR"`, `transport_error` | ✕ "Not listening" | StateScreen: "RaceLab isn't listening on 127.0.0.1:20440" + **Open Diagnostics** action + raw error in disclosure |
| First run | `setup.first_run` | ○ "Set up Forza Horizon 6" | Full first-run screen (6 steps + live detection line) |
| Setup just completed | `resolveSetupStage → detected` | ● "Connected" | Success screen with **Continue** (existing behaviour) |
| No game detected | `LISTENING`, `DISCONNECTED`, `STARTING` | ○ "Waiting for Forza Horizon 6" | StateScreen, dimmed dashboard skeleton behind it |
| Detecting | `PROBING` | ◐ "Detecting game…" | same, with subtle progress indicator |
| Connected, not driving | `CONNECTED_IDLE` / `SESSION_ACTIVE` with inactive frame | ● "Connected · in menus" | Dimmed dashboard + one-line state |
| Degraded | `DEGRADED` / `stale` | ◐ "Telemetry degraded" | Dimmed dashboard + warn line |
| Live session | `frame.active` | ● "Live" | Full dashboard |
| Recording | `recorder.recording` | `● REC 12:04` element | — |
| Session ending (grace) | `session.state === "GRACE"` | ◐ "Paused · session ends in 8 s" | Dimmed dashboard + countdown |
| Storage warning | `retention.over_budget`, `retention.last_error`, `failed_deletions > 0`, `settings.last_error` | — | Alert (warn) in Sessions and Settings › Storage |
| Recorder drops | `recorder.recorder_dropped_frames > 0` | ◐ on REC element | Alert in Sessions (current-session drops only, as today) |

Sessions-side states:

| State | Source | Presentation |
|---|---|---|
| No sessions yet | list empty, no error | StateScreen: "No sessions yet — drive with Data Out on and RaceLab records automatically" |
| Recording now | `recorder.recording` | pinned live row at top of list (duration ticking from recorder poll, not selectable) |
| Session finalizing | manifest `status: "recording"` that is not the active `recorder.session_id` | row badge "Finalizing" (no new semantic — it is what the manifest says) |
| Interrupted / recovery | `recoveryLabel`, `recoveryNote` | row badge + detail Alert using existing sentences |
| Checking recordings | `storage.recovery.pending/scanned` | list-header progress line |
| Unreadable folders | `recent.unreadable` | list-header warn line |
| Analysis loading / queued / analyzing / available / not analyzed / failed / unsupported | `analysisBanner()` (unchanged) | Lifecycle strip in detail header: icon + headline; detail sentence below; **Re-run analysis** only where it is offered today |

No `alert()`/`confirm()` anywhere (there are none today; keep it that way).
Raw backend error strings are always shown, but inside a "Technical details"
disclosure in mono under a human title — never as the only text.

## 9. Motion, responsiveness, performance, accessibility

**Motion** (`--dur-1: 120ms`, `--dur-2: 180ms`, `--dur-3: 280ms`,
`--ease: cubic-bezier(.2,0,0,1)`):
- Live ⇄ idle: dashboard opacity/saturation crossfade 280 ms.
- Workspace/tab switch: 120 ms fade of the content area only (no slide).
- Lifecycle pill change (queued → analyzing → available): 180 ms colour/icon.
- Bars: width transition ≤ 50 ms linear (one poll interval) — no easing that
  would draw values between samples for longer than a frame. Numbers never tween.
- REC dot: slow 2 s opacity pulse; Detecting/analyzing: 1 s indeterminate bar.
- `prefers-reduced-motion`: all of the above become instant.

**Responsiveness** — container-width driven (CSS container queries, available
in WebView2), not viewport:
- ≥ 1500 px content: Overview 3 columns (hero · inputs · corners).
- 1100–1499: layout above (primary target 1280×720 / 1366×768).
- < 1100: sidebar becomes 56 px rail, Overview stacks hero over inputs.
- < 820 (window min 720): single column; Sessions list collapses to a
  drop-down above the detail.
Verified at 1280×720, 1366×768, 1920×1080, maximized, and 900×700.

**Performance** — no new polling, no new subscriptions, no frame history; live
view models still built once per snapshot. Sessions/Settings/Diagnostics
subtrees memoised so 20 Hz updates touch only Live + top bar. SVG timeline is
built once per analysis document (memo on `session_id` + `analyzed_at`).

**Accessibility** — AA contrast for all text tokens; state never by colour alone
(icon + text kept from today); `aria-current` on nav, `role="tablist"` with
arrow-key tabs; live regions only for state changes, never for 20 Hz values;
ⓘ tips reachable by keyboard; visible focus everywhere.

## 10. Decisions needed before Stage B

**D1 — Window size (touches `src-tauri/tauri.conf.json`).** Default is 1120×760
with min 720×560, below the stated 1280×720 target. Proposal: default
1280×800, min 960×640. This is packaging config, not product logic, but it is
"packaged runtime behaviour". *Recommend: change it; otherwise design for 1120
as the real default.*

**D2 — Analysis status refresh for the selected session.** Today it is read once
on open. Options: (a) re-read the selected analysis whenever
`recorder.completed_sessions` changes plus a manual "Check again" (no new loop;
does not cover queue progress); (b) a bounded view-local re-read every 2 s
*only* while the selected analysis is `queued`/`analyzing`, stopped on any
terminal state, selection change or unmount — requires amending the
architecture test that pins pollers to three hooks. *Recommend (b)*: it reads
one small state object and removes the "reopen it in a moment" instruction.

**D3 — IA merges.** Inputs → Overview, Race → Overview + Motion, Tires +
Suspension → Corners, Dynamics → Motion. No field is dropped (§2). *Confirm.*

**D4 — Channel colours.** Throttle green / brake red as the only semantic hues
on Live, plus a neutral single-hue intensity ramp for tyre temperature and slip
(no thresholds). *Confirm*, or keep all bars neutral.
