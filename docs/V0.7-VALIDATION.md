# V0.7 — Dashboard validation

2026-09-20. V0.7 is **code-complete and not frozen**. No manual Forza Horizon 6
validation of V0.7 has been performed; the required procedure is at the end of
this report. Design and architecture: [V0.7-DASHBOARD.md](V0.7-DASHBOARD.md).

## What did not change

`git diff v0.6.0 -- src-tauri/` produces **no output**. The entire backend is
byte-identical to the V0.6 freeze, including every frozen file:

```
git diff --stat v0.6.0 -- src-tauri/src/ingress.rs          # empty
git diff --stat v0.6.0 -- src-tauri/src/packet.rs           # empty
git diff --stat v0.6.0 -- src-tauri/src/capture.rs          # empty
git diff --stat v0.6.0 -- src-tauri/src/capture_format.rs   # empty
git diff --stat v0.6.0 -- src-tauri/src/session_recorder.rs # empty
git diff --stat v0.6.0 -- src-tauri/src/session_format.rs   # empty
git diff --stat v0.6.0 -- src-tauri/src/session_store.rs    # empty
```

No blocker requiring a backend change was found, and none was made. No Tauri
command was added, removed or changed. `TelemetryFrame` field semantics, the
RLFRAMES v1 format, the session manifest schema and the V0.5.1 connection and
session lifecycle are all untouched. The crate and package versions stay at
`0.6.0`; the version bump belongs to the freeze commit, after manual validation.

## Known limitations

1. **Tires, Suspension and Race render structure without data.** Canonical
   telemetry has no per-wheel, suspension or lap/race channel. Each view states
   why and points at Diagnostics. See the table in
   [V0.7-DASHBOARD.md](V0.7-DASHBOARD.md); resolving this is backend work that
   needs captured-packet evidence for bytes 68..211 and verified units, and was
   deliberately not attempted in a frontend release.
2. **Engine shows RPM only.** Power, torque, boost and fuel stay unavailable for
   the same reason.
3. **Gear is always `—` for FH6.** By design, until gear semantics are
   established.
4. **`get_live_telemetry` still serializes the whole `sourceSpecific.fh6`
   envelope**, including the 144-byte opaque region and the 32-entry float map,
   at 20 Hz. This is unchanged V0.6 behaviour and was measured only as build
   output, not profiled under load. If it ever matters, the fix is a narrower
   backend snapshot, not a UI change.
5. **No renderer-level frontend tests.** See above.
6. **The dashboard has not been run against real FH6 traffic.** Everything below
   is still pending.

## Manual FH6 acceptance procedure — REQUIRED, NOT YET PERFORMED

Run `pnpm tauri dev` on the Windows machine with FH6 configured to send
telemetry to this computer on UDP `20440`.

**A. Game closed**

1. Start RaceLab with FH6 not running.
2. Status bar reads `No game detected`, `Connection: Waiting for game`,
   `Health: No signal`, `Session: No session`, `Recording: Not recording`.
3. Open Overview: the empty state reads "Waiting for game"; speed, RPM, gear and
   every input read `—`. **No driving metric shows a number.**
4. Visit Engine, Dynamics, Tires, Suspension, Inputs and Race. Confirm the same
   empty state and no stale values anywhere.

**B. FH6 starts**

5. Launch FH6 and reach the main menu. Diagnostics → Protocol should show the
   packet rate rising and `FH6 inactive` incrementing.
6. Status bar moves through `Detecting game` to `Connected`, and the game reads
   `Forza Horizon 6`. Record how long detection took.

**C. Driving**

7. Start a free-roam drive.
8. Overview: speed and RPM update smoothly, the RPM bar tracks the range,
   throttle/brake/steering bars respond to your inputs, Vehicle ID is populated,
   Session shows `Session active` and a running duration, Recording shows
   `Recording`.
9. Engine: current/idle/max RPM populated and plausible. Power, torque, boost,
   fuel read `—` — expected.
10. Dynamics: speed, acceleration X/Y/Z (and g), velocity, angular velocity,
    yaw/pitch/roll and position all update.
11. Inputs: all five channels respond. Press the clutch and handbrake if you
    have them; confirm they are not stuck at `—`. Steer left and confirm the
    percentage goes **negative** and the bar grows left of centre.
12. Tires and Suspension: four corners in the order FL, FR, RL, RR, all `—`
    with the stated reason. Confirm no corner claims a value.
13. Race: lap and timing fields `—`; Game clock advances.
14. Diagnostics: `Receive errors 0`, `Subscriber drops 0`, `Invalid FH6 0`,
    `Protocol confidence 100%`, recorder `Current session drops 0`. Record the
    packet rate and valid frame rate; they should match at roughly 60-75 Hz.
15. Note whether the UI feels smooth and readable at a glance while driving.

**D. Menu (grace)**

16. Pause or open a menu so telemetry goes inactive.
17. Status bar shows `Telemetry paused` and `Session grace · N s left`, counting
    down.
18. Overview shows the grace empty state. **Speed and RPM must read `—`, not the
    last driving values.** Check Engine, Dynamics and Inputs too.

**E. Return to driving**

19. Resume driving within the grace period.
20. The session ID in Diagnostics/Sessions is the **same** session; the duration
    keeps counting from before the pause; the dashboard resumes immediately.

**F. Long menu (completion)**

21. Stay in a menu past the grace period (10 s by default).
22. Status bar shows `Session completed`, then `No session` on the next start.
23. Sessions lists the completed session, newest first, with Completed status,
    duration, max and average speed.

**G. Sessions**

24. Open the session. Confirm details, summary metrics, Data quality
    `Complete` and `Recorder drops 0`.
25. Confirm no frame stream is loaded and the view opens instantly.

**H. Diagnostics**

26. Confirm the V0.3 Raw Capture panel still starts and stops a capture and
    saves a file.
27. Confirm the raw gear code appears **only** here, labelled `Gear (raw code)`.
28. Confirm packet counters, hex preview, hub stats and the listener stop/start
    controls all still work.

**I. Navigation and polling**

29. Switch rapidly between all nine views for ~30 seconds while driving.
30. Return to Diagnostics and confirm the packet rate and valid frame rate are
    unchanged and receive errors are still 0 — evidence that view switching did
    not disturb ingestion.

Record the results here and only then bump the version and tag `v0.7.0`.
**V0.7 must not be called frozen until section A-I passes on real hardware.**
